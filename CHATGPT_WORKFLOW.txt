SMART SCHEDULE — CHATGPT UPDATE INSTRUCTIONS

When sending a scheduling request to ChatGPT:

1. Open update.html to view the current master profile. Select Create update on an existing profile item or add only what changed, then download the changes-only JSON update file. A clear plain-text scheduling request is still accepted as a fallback.
2. Select the GitHub connector.
3. Tell ChatGPT:

   Update ITLegend-co/scheduling-system directly. Read data/schedule.json first, arrange my request in a suitable free date and time, validate it, update meta.lastUpdated, generate the calendar feed, and commit the change to main. Do not remove existing events unless I request it.

JSON UPDATE FILE RULES

- Accept format: "smart-schedule-update" with version: 1.
- Treat instructions.mode: "changes-only" as mandatory.
- Preserve every unmentioned event. Never replace the full schedule with the update file.
- Apply each changes[] item according to action: add, update, complete, or remove.
- For update, complete, or remove, match existingEventId first. If it is missing, match using the exact title and date; ask if the match is ambiguous.
- Use autoScheduleMissingTimes and createDeadlineWhenMissing from the file when arranging incomplete items.
- Ignore requestId when generating the final schedule event ID; create or preserve a stable event ID instead.

MASTER PROFILE RULES

- data/schedule-profile.json is the structured replacement for help update schedule.txt and is displayed by update.html.
- Treat smart-schedule-profile as background context, not as a request to replace data/schedule.json.
- A smart-schedule-update file contains the user's requested changes. Apply it to the existing schedule and preserve unmentioned events.
- When a request changes long-term work rules, ongoing tasks, meetings, or personal preferences, update the matching profile entry as well as any affected schedule events.

ARRANGEMENT RULES FOR CHATGPT

- Use the Asia/Kuala_Lumpur timezone unless the request says otherwise.
- Treat existing confirmed events as fixed.
- Keep the configured buffer between separate commitments when possible.
- Place flexible work inside the configured workdays and working hours.
- Schedule urgent and high-priority items before lower-priority flexible work.
- Respect deadlines, preferred times, travel time, and dates to avoid.
- Never create an accidental overlap. Use allowOverlap: true only when explicitly intended.
- If no suitable slot exists, do not guess. Record the issue in the GitHub reply and ask for an alternative.
- Give each new event a stable lowercase ID, for example: prepare-monthly-report-2026-08-18.
- Use ISO date-times with the Malaysia offset, for example: 2026-08-18T09:00:00+08:00.
- For all-day events, use YYYY-MM-DD and set allDay to true.
- Update meta.lastUpdated every time the schedule changes.
- Run: node scripts/validate-schedule.mjs
- Run: node scripts/generate-ics.mjs
- Commit only the intended scheduling changes.
